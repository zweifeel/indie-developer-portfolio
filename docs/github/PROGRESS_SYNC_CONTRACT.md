## 1. Architectural Scope & Purpose

This contract defines how incoming GitHub webhooks (pushes, pull requests, and releases) map into SleepyKoala Studio's Canonical Progress Metadata Schema v2 (`docs/metadata/METADATA_CONTRACT.md`).

It establishes strict invariants to preserve data integrity, editorial oversight, and the separation between engineering milestones and public marketing visibility.

---

## 2. Core Invariants

### 2.1 Editorial Gating (Publication Status Invariant)
> **INVARIANT 1:** All progress events generated by automated GitHub webhooks are created with `publicationStatus: 'draft'`.

Under NO circumstances will a GitHub webhook push, merge, or release automatically set `publicationStatus: 'published'`. Public visibility requires deliberate review and approval in the SleepyKoala CMS Web Admin.

### 2.2 Lifecycle Decoupling (Implementation Status Invariant)
> **INVARIANT 2:** GitHub commits, pushes, and PR merges NEVER automatically alter a project's `implementationStatus` or `status` to `'completed'` or `'RELEASED'`.

Commit messages claiming completion (e.g. `feat: finished Mobile Kasir implementation`) are treated purely as changelog text notes. Progress status transitions remain exclusively governed by verified test reports and signed administrative actions.

## 3. GitHub Event Mappings

### 3.1 Push Event (`eventType: 'general_update'`)
```json
{
  "id": "evt_{slug}_push_{shortSha}_{timestamp}",
  "eventType": "general_update",
  "title": "[{branch}] {sanitizedFirstLineOfCommitMessage}",
  "description": "{sanitizedFullCommitMessage}",
  "timestamp": "{commitTimestampISO}",
  "publicationStatus": "draft"
}
```

### 3.2 Merged Pull Request (`eventType: 'feature_released'`)
```json
{
  "id": "evt_{slug}_pr_{prNumber}_{timestamp}",
  "eventType": "feature_released",
  "title": "Merged PR #{prNumber}: {sanitizedPrTitle}",
  "description": "{sanitizedPrBody}",
  "timestamp": "{mergedAtISO}",
  "publicationStatus": "draft"
}
```

### 3.3 Published Release (`eventType: 'milestone_reached'`)
```json
{
  "id": "evt_{slug}_rel_{tagName}_{timestamp}",
  "eventType": "milestone_reached",
  "title": "Release {releaseNameOrTag}",
  "description": "{sanitizedReleaseBody}",
  "timestamp": "{publishedAtISO}",
  "publicationStatus": "draft"
}
```

## 4. Public Projection & Whitelist Filtering

When progress metadata is served to the public portfolio (`/api/projects/:slug`), `PUBLIC_METADATA_POLICY.md` filtering rules apply:
1. Only events where `publicationStatus === 'published'` are projected.
2. Events in `draft` or `archived` states are stripped.
3. Private repository names, branch branches containing internal task codes, and developer emails are completely removed.
